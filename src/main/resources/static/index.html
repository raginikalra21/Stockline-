How the strategies differ

Naive reads balances and writes absolute values without a version check or row lock. A simulation-only read barrier aligns stale reads; database writes, orders, and ledger movements remain real transactions.

Optimistic updates only the row version it read. A stale update rolls back and retries with bounded exponential backoff and full jitter.

Pessimistic locks every candidate warehouse row with SELECT FOR UPDATE in SKU and warehouse-code order before checking availability.

All runs use isolated H2 databases, the same schema, READ_COMMITTED, and identical warehouse stock distribution. At this isolation level, a read can become stale before an unguarded write; other database engines or stricter isolation levels may block, abort, or serialize that race differently. H2 results help compare behavior locally; they do not predict production database performance.
